# QUERY_MODEL — диалог, операции и формат ответа

Код: `ksys/dialogue/intents.py` (классификация), `ksys/dialogue/session.py` (исполнение), `ksys/query/*` (ответы), `ksys/cli/main.py` (печать).

## 1. Классификация запроса
Упорядоченный список регулярных правил: первое совпадение побеждает, имя правила возвращается в ответе (`OPERATION: VERIFY (verify)`). Если ни одно правило не подошло: вопрос (`?`) → ASK, иначе → ASSERT в режиме **предпросмотра**.

| Операция | Примеры фраз | Действие |
|---|---|---|
| ASSERT | «Добавь факт: …», «Добавь правило: …», «Запомни: …» | предпросмотр; запись только с `--yes` |
| ASK | «Использует ли Алекс Python?», «Кто использует Python?» | вердикт Белнапа / связывания wh-переменных |
| VERIFY | «А правильно ли, что X приводит к Y?», «Проверь, что …» | оценка через граф аргументов |
| HYPOTHESIZE | «Проверь гипотезу, что …», «Гипотеза: …» | то же + сохранение гипотезы (`--yes`) |
| EXPLAIN | «Почему ты считаешь, что X?», `explain F:…` | дерево доказательства или честный `NO_PROOF` |
| TRACE | «Откуда взялся этот вывод?» | решения человека, правила и фрагменты-источники |
| FIND_CONTRADICTIONS | «Какие факты противоречат X?», «Найди противоречия» | противоречия + базис + зависимые |
| DERIVE | «Что следует из X и Y?» (или `X; Y`) | гипотетический вывод на копии движка, без записи |
| RETRACT | «Удали факт F:…» | предпросмотр затронутого; запись с `--yes` |
| REVISE | «Исправление: возраст Алекса было 10, а не 12» | supersede + список инвалидированных выводов |
| DEFINE | «Определи понятие X», «Что такое X?» | определения, классы, экземпляры |
| COMPARE | «Сравни X и Y» | общие и различающиеся классы, прямые отношения |
| GENERALIZE / SPECIALIZE | «К чему относится X?» / «Какие бывают X?» | надклассы / экземпляры и подклассы |
| UNKNOWNS | «Какие неизвестные остаются?» | открытые гипотезы, решения без опоры, неполнота схемы, неоценённая уверенность, непросмотренные заявления |
| WHAT_IF | «Что будет, если удалить факт X?» | DRed на копии: что исчезнет, что сохранится благодаря другим обоснованиям |

`этот вывод` / `это` ссылаются на первый результат предыдущего ответа в сессии. Цели запросов можно указывать ID (`F:…`, `D:…`, `#seq`) или текстом — текст формализуется тем же языковым слоем.

## 2. Формат ответа (Response)
```
OPERATION: <операция> (<правило классификации>)
STATUS:    PROVEN | DISPROVEN | BOTH | UNKNOWN | SUPPORTED | CONTESTED | REFUTED | NO_PROOF | PREVIEW_* | COMMITTED | …
ANSWER:    человекочитаемый ответ
EVIDENCE / COUNTER_EVIDENCE / DERIVATION / CONTRADICTIONS / UNKNOWNS / NOTES / PREVIEW / …
```
`--json` выдаёт ту же структуру машиночитаемо (`{op, rule, status, answer, sections, committed}`).

Принципы:
- **UNKNOWN вместо FALSE**: отсутствие поддержки никогда не печатается как «нет»;
- **NO_PROOF вместо фальшивого объяснения**: если вывода нет, объяснение не строится;
- **AMBIGUOUS вместо догадки**: запрос с несколькими прочтениями возвращает варианты, а не выбирает сам;
- запросы без `--yes` ничего не пишут в журнал (проверяется тестом `test_full_conversation`).

## 3. Время и контекст в запросах
`--at YYYY-MM-DD`: учитываются только утверждения, истинные на эту дату. Без даты в ответ попадают утверждения с интервалами, и примечание просит уточнить дату. Контекст утверждения (`in работ`) показывается в свидетельствах.

## 4. Предпросмотр (human-in-the-loop)
```
ORIGINAL TEXT → interpretation → FORMAL (KSF) → CANONICAL (пересказ)
+ проверки схемы (diagnostics) + конфликты с известным (conflicts) + «уже известно» (known) + «ранее отклонено» (rejected_before)
ACTIONS: ACCEPT | EDIT | REJECT | SPLIT | MERGE | MARK AS CLAIM | MARK AS HYPOTHESIS | MARK AS UNKNOWN
```
Для кандидатов импорта: `knowledge review list|show|accept|reject|defer|merge|resolve` (см. `README.md`).
