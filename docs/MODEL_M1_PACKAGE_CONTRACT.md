# MODEL-M1 — контракт комплектности и совместимости весов

**Статус: первая проверяемая версия контракта v1; не полный пакет и не
готовый Android inference.** Загрузка/импорт одного `.gguf`/`.onnx` остаются
независимыми от установки токенизатора или движка.

## Что теперь показывает карточка модели

Помимо фактического размера файла и SHA-256, Android показывает:

- происхождение из аудированного каталога (если SHA, роль и **формат**
  совпадают) либо пометку `user-imported/unverified`;
- заявленную лицензию или `unverified`, без автоматического принятия;
- предполагаемый класс движка (`llama.cpp/GGUF` или `ONNX Runtime Mobile`)
  с обязательным предупреждением **«НЕ ПРОВЕРЕН»**;
- версию контракта комплекта `v1` и конкретный список недостающих
  проверок по четырём отдельным ролям.

| Класс | Недостающие составляющие / проверки |
|---|---|
| Эмбеддинги | Tokenizer; для ONNX — config; pooling, query/passage и совместимый Android backend |
| Генеративная LLM | Tokenizer, chat/prompt template; для ONNX — config; совместимый backend |
| Реранкер | Tokenizer, парный вход/скоринг; для ONNX — config; совместимый backend |
| Персонализация | Версионированные признаки/метки и backend; GGUF помечается неподдерживаемым форматом для этой роли |

Для всех ролей требуется **проверенная ревизия исходного репозитория**.
Ссылка на `resolve/main` не является фиксированной ревизией, хотя
известный SHA-256 защищает **байты одного файла**. Пользовательские
файлы требуют самостоятельной проверки источника и лицензии.

Контракт специально всегда возвращает `runnable=false`: сохранённый
весовой файл не исполняется; нет скрытого автопоиска tokenizer, загрузки
веса в RAM, выбора backend или отправки данных в API. Указанные
«предполагаемые» движки — только направления для будущей совместимости,
не результат замеров на Redmi Note 13.

## Оставшийся MODEL-M1

1. Создать **подписываемый/проверяемый по SHA** полный пользовательский
   пакет с manifest, weight, tokenizer/config и фиксированной ревизией;
   каждый компонент хранить приватно и атомарно, не смешивать версии.
2. Проверять ONNX операторы, input/output signatures, tokenizer/pooling;
   GGUF архитектуру, токенизатор, chat/rerank template и требования ABI.
3. Gated/licensed HF-случаи и ручное получение прав, без хранения
   учётных данных в манифесте.
4. Android UI и физический QA: большой шрифт/TalkBack, разные версии,
   повреждение/низкое место, отмена, импорт стороннего файла, выключение
   каждого из четырёх типов. Никаких личных заметок в тестах.

Этот контракт является промежуточной гарантией **отсутствия ложного
статуса «готово к запуску»**, а не доказательством наличия движка.
