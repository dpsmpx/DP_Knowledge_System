# MODEL-M0 — разрешение на передачу текста внешнему провайдеру

**Статус: частичная реализация Android-интеграции; не закрытый этап M0.**
Нормативная последовательность `M0 → M8` и условия приёмки находятся в
[`LOCAL_AI_MODELS_PLAN.md`](https://github.com/dpsmpx/DP_Knowledge_System/blob/main/docs/LOCAL_AI_MODELS_PLAN.md).

## Реализованный инвариант

- Без ИИ, без конфигурации или при отказе сети основной Markdown/FTS/граф,
  аудит и журнал решений работают отдельно. Android-local провайдер не
  разрешает HTTP. Сетевые PC/LAN/Tailscale и cloud endpoint остаются
  необязательными. Никакого автоматического fallback Android → API нет.
- Чат LLM, семантический запрос и ручная операция построения эмбеддингов
  начинаются только после отдельного диалога согласия. UI создаёт
  **неперсистентное разрешение**, привязанное к endpoint, модели и операции.
- Низкоуровневые `KnowledgeLlmClient.ask` и `KnowledgeEmbeddingClient.embed`
  теперь требуют объект `KnowledgeNetworkApproval.Permit` и вызывают
  `consume()` **до открытия соединения**. Нет разрешения, несовпадение
  endpoint/model/role, просрочка или повторный одноразовый вызов — нет сети.
- Разрешение на LLM привязано SHA-256 к **точному preview вопроса с
  выдержками**, разрешение на одиночный семантический запрос — к точному
  тексту запроса. Они действуют для **одного** вызова.
- Массовая индексация подтверждается **по конкретному заранее составленному
  списку исходящих batch**. Пользователь видит прокручиваемый полный текст
  **каждого** подлежащего отправке chunk, имя исходного файла и номер
  фрагмента (имена файлов не отправляются в embedding API). При одном
  подтверждении передаётся не более 128 000 символов фрагментов;
  остаток требует новой ручной операции и согласия.
- Permit хранит только SHA-256 каждого согласованного batch и разрешает
  **строго ту же последовательность** текста; подмена, перестановка,
  повтор или дополнительный запрос отвергаются до подключения к сети.
  Резюмирование checkpoint вычисляется без изменения индекса до согласия,
  затем сверяется при запуске. Изменение источника или checkpoint
  прерывает весь запуск: остальные batch нельзя незаметно пропустить.
  Максимальный срок разрешения — 90 минут. Отмена/уничтожение Activity
  отзывает его; в токене нет путей, заметок, API-ключей и ответов.

## Осталось до закрытия M0

1. Проверить в **ручном Android UI тесте**, что весь длинный предпросмотр
   доступен для чтения и работы со скринридером, а кнопка «Отправить»
   действительно требует явного действия пользователя. Нужны также
   сценарии фона/поворота/уничтожения Activity для отказа от согласия.
2. Проверить отдельно PC/LAN/Tailscale и облачный сервис с недоступной
   сетью, неправильным ключом, ошибкой HTTP, задержкой, отменой,
   отсутствием согласия и отсутствием автоматического fallback.
3. Аппаратный QA Android 15, сканирование сети/логов с **только
   синтетическими** заметками, TalkBack/поворот/фон/отмена; отдельно от
   Android JVM и Python CI.

**Нет утверждения о готовой Android inference-модели.** Это граница
передачи в существующем сетевом клиенте, а не замена M1/M3–M8.
