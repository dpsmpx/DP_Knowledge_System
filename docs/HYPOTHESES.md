# HYPOTHESES — проверка гипотез

Код: `ksys/query/hypothesis.py`.

## Алгоритм
1. **Нормализация:** текст → контролируемый язык или KSF → одно утверждение IR (неоднозначность и неразрешённые ссылки → ошибка с вопросом человеку, без догадки).
2. **Прямые подтверждения и опровержения** в слое `auth` и в слое `full` (с заявлениями). Временная семантика: интервал свидетельства должен **покрывать** интервал гипотезы, контекст — быть совместимым. Частичное временное покрытие выводится как примечание.
3. **Правила:** свидетельство может быть выведенным. Для каждого строится дерево доказательства.
4. **Явные аргументы человека** (`Evidence` → цель `H:`/`A:`/`F:`) добавляются в граф.
5. **Граф аргументов** с предпочтением `auth > claim`, grounded-разметка.
6. **Статус:**

| Статус | Условие |
|---|---|
| PROVEN | IN-аргумент «за» — логический вывод из авторитетного знания; нет IN «против» |
| SUPPORTED | IN «за» только из заявлений или аргументов человека; нет IN «против» |
| CONTESTED | равносильные аргументы за и против (UNDEC) |
| REFUTED | IN «против», нет IN «за» (принятый факт сильнее заявления) |
| UNKNOWN | аргументов нет |

7. **Для UNKNOWN** перечисляются правила, из которых гипотеза могла бы следовать, и их недостающие посылки. Пример: «нужно знать: `works_with(алекс, python)`».

Статистические оценки, вероятности и «уверенность модели» не используются.

## Результат
`HypothesisResult{hypothesis, status, answer, supporting[], counter[], conflicts[], missing_premises[], proofs[], notes[]}`. Каждый аргумент: `{argument, label IN/OUT/UNDEC, strength, basis[записи], ksf, id}`.

## Сохранённые гипотезы
Гипотезу можно сохранить в журнал (`hypothesis …` / «Гипотеза: …»). Запись получает статус UNKNOWN как *утверждение*, а её оценка вычисляется заново при каждом изменении знаний. Список открытых гипотез входит в `knowledge unknowns` и `reports/HYPOTHESES.md`.
