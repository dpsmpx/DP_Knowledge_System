# MODEL-M2 — ручные CPU-микробенчмарки четырёх ролей

**Срез:** полностью синтетический и локальный, без inference. Сборка и
JVM-проверки должны быть подтверждены Android CI; показатели реального
устройства пока не измерены.

## Пользовательский сценарий

В **Управление локальными моделями → [одна из четырёх ролей]** находится
**«Запустить синтетический CPU-тест…»**. Отдельное подтверждение заранее
сообщает, что тест не запускает ни установленный, ни предлагаемый файл весов,
не касается приватной библиотеки и может кратковременно загрузить процессор.
Кнопка управления временно становится **«Отменить бенчмарк»**; нажатие
вызывает `Future.cancel(true)` и скрывает устаревший результат. Поворот,
уничтожение Activity и запуск другой модельной операции не публикуют
старый отчёт (generation guard). Ничего не скачивается и не сохраняется.

## Четыре фиксированные нагрузки

| Роль | Синтетический цикл за повтор | Условные единицы |
|---|---|---:|
| Embeddings | Косинусное сходство векторов float32 | 12 288 пар |
| Generation | Выбор максимального логита из 512 вариантов | 512 шагов |
| Reranking | Произведения векторов и сортировка кандидатов | 16 384 кандидата |
| Personalization | Обновление 64 весов простого линейного классификатора | 8 192 примера |

Входные числа генерируются предсказуемо только в памяти (без генератора
системной случайности, конфигурации пользователя или моделей). Каждая роль
выполняет один прогрев и **7 измеряемых повторов** с проверкой отмены;
каждый повтор ограничен **2 секундами**. Медленный/прерванный тест не
показывает частичный результат. Отчёт содержит p50/p95 времени повтора в
микросекундах, три **выборочных** значения Java-heap (до/максимальное
наблюдённое/после), условное число операций и контрольную сумму.

## Строгие ограничения интерпретации

- Разные операции и единицы между ролями **нельзя сравнивать как рейтинг
  производительности моделей**. Это только базовая CPU-диагностика для
  будущих измерений; JIT, энергосбережение, нагрев и сборщик мусора
  влияют на p50/p95 даже на одном устройстве.
- Java-heap — не RSS, не native heap, не максимальная RAM процесса или
  модели. Это *снимки* в несколько моментов выполнения, а не истинный пик.
- Тест **не** измеряет скорость токенизации, настоящую выдачу токенов,
  эмбеддинги, качество, нагрузку GPU/NPU, требования конкретного runtime,
  совместимость, батарею или термальные показатели. Отдельные ручные
  device/model-specific бенчмарки остаются незавершённым MODEL-M2/M3–M8.
- Ни веса/компаньоны, ни заметки/журнал, ни URL, ни AI API не читаются.
  Никакой фоновой периодической задачи, автоматического запуска или
  записи результатов в индекс/на диск нет.

## Проверка

- JVM: все четыре роли, одинаковые контрольные суммы при повторном
  запуске, неизменные единицы работы, отсортированные p50/p95,
  неотрицательные снимки heap, запрет null-роли и прерывания.
- Android CI: RU/EN ресурсы, обе debug-конфигурации и JVM-тесты.
- Физическая приёмка отдельно: кнопка подтверждения/отмены, быстрый
  повторный запуск, процесс death/rotation, TalkBack, энергосбережение,
  200% размер шрифта и отсутствие нежелательного обращения к сети.
