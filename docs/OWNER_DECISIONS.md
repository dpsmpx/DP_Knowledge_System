# Решения, которые необходимо подтвердить владельцу

**Состояние:** вопросы открыты на 2026-11-18. Ответов в этом документе нет;
предложенные временные ограничения — **не согласие владельца**. После ответа
записать решение с датой, обоснованием, затронутыми этапами и тестами; закрыть
или уточнить соответствующие долги в [TECHNICAL_DEBT.md](TECHNICAL_DEBT.md).

| ID | Вопрос | Почему это меняет разработку | Временная безопасная граница |
|---|---|---|---|
| **Q-01** | Что является обязательным для **первой полноценной версии**: замена Obsidian только на Android или одновременно ПК/веб? | Архитектура интерфейса, синхронизация и приоритеты | Первая платформа — Android; ПК/веб не обещать |
| **Q-02** | Нужно ли оставаться совместимыми с Android **7.0 / API 24**, или можно повысить минимум? | Chaquopy, криптография, современные API и поддержка старых устройств | Сохранять API 24 до явного решения |
| **Q-03** | Какой **реальный целевой размер** библиотеки (примерно файлов, общий объём, размер самых крупных файлов) и какие допустимые время/память/расход батареи? | Лимиты 200k файлов, 2 MiB и 128 passages, индексирование и тестовые бюджеты | Обязательно указывать неполный охват, не обещать скорость |
| **Q-04** | Может ли интеллектуальная система **автоматически менять текст, теги, пути и связи**, или любые такие изменения разрешаются только после предпросмотра? | Необратимые операции, authority и UX | Ни одной автоматической записи в заметки; только отдельно одобренные операции |
| **Q-05** | Достаточно ли Syncthing/внешней синхронизации Markdown, либо нужен **встроенный sync** файлов, индексов и авторитетных решений? | Конфликты файлов, журналов, шифрование и непротиворечивый merge | Не внедрять встроенный sync и авто-merge журнала |
| **Q-06** | Какие LLM-режимы обязательны: **ПК по LAN/Tailscale**, облачные API, локальная модель на телефоне? Какой режим по умолчанию? | Сеть, latency, аккумулятор, данные, стоимость | Детерминированное ядро offline; сеть только с отдельным согласием |
| **Q-07** | Нужно ли хранить API-ключи в Android Keystore, или сохраняем ввод **для каждого запроса**, как сейчас? | UX против угрозы компрометации и права на передачу | Не сохранять секреты, пока не решено |
| **Q-08** | Какая политика взаимодействия с ошибками/противоречиями: только **советы и вопросы**, пакетное подтверждение или допускается автоматическое принятие некоторых решений? | Можно ли изменять формальную авторитетную базу без человека | Только явное решение пользователя; `UNKNOWN` не превращать в факт |
| **Q-09** | В каком виде нужна главная UI: оставить редактор Markor с мощным Knowledge Hub или радикально заменить навигацию/UX? | Объём redesign, поддержка оригинального кода, тестирование | Улучшать без ломки редактора и форматов |
| **Q-10** | Где распространять **первый полный релиз**: GitHub, F-Droid, RuStore, Google Play или несколько площадок? | Policy, подпись, package ID, storage permissions, licensing, CI | Сначала проверенный signed GitHub prerelease |
| **Q-11** | Нужна ли встроенная **зашифрованная синхронизация/автоматические резервные копии** и куда их сохранять? | Восстановление после потери устройства, ключи, облако, merge и экспорт | Только явный локальный экспорт/импорт, без облачного backup |
| **Q-12** | Какой из направлений после стабилизации Android важнее: семантическая точность, скорость на 200k заметок, UX, on-device AI, встроенный sync, граф знаний? | Порядок Stage 16–22 и ресурсы на исследования | В первую очередь безопасность данных, затем надёжность и основные UX-сценарии |

**Минимум для планирования ближайшего PR:** Q-03 (масштаб и бюджеты), Q-04
(право на запись), Q-08 (границы авторитета). Для стратегического roadmap
нужны также Q-01, Q-05, Q-06, Q-09, Q-10, Q-12. Остальные можно уточнять
перед конкретным этапом. Вопросы не требуют раскрывать содержимое личного
vault, пароль, ключ API или личные данные.
