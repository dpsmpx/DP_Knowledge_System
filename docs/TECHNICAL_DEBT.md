# DP Knowledge System — реестр технических долгов

**Проверено по состоянию на 2026-11-18.** Это перечень **известных**, а не
гарантированно всех возможных дефектов. **Продуктовые решения владельца
утверждены 2026-11-18** в [OWNER_DECISIONS.md](OWNER_DECISIONS.md).
Статусы: **открыт** — не внедрено/не проверено; **частично** — есть прототип,
ручная проверка или ограничения; **решение** — конкретная инженерная
деталь ещё проектируется; **отложен** — не в ближайшем v1.

Источники: исходники и документация `main`,
[интеграционный roadmap](https://github.com/dpsmpx/DP_Knowledge_System/blob/feature/knowledge-android/docs/ANDROID_ROADMAP.md),
[PR #7](https://github.com/dpsmpx/DP_Knowledge_System/pull/7),
[PR #16](https://github.com/dpsmpx/DP_Knowledge_System/pull/16).
Если запись противоречит фактическому тесту, обновить её с доказательством.

## P0 — установка, целостность, безопасность и выпуск

| ID / статус | Долг и риск | Условие закрытия |
|---|---|---|
| **REL-01 / частично** | **Установка состоялась** после повторной загрузки через Termux (сообщение владельца); несколько offline-функций работают. Исходная браузерная загрузка имела другой SHA-256. Причина отличия исходных байтов не доказана. | Сохранить правильный файл/hash, повторить установку из официального release и автоматизировать signed-APK smoke-test; полный QA отдельно |
| **CI-02 / открыт** | CI проверяет сборку, идентификатор пакета и подпись, но не установку итогового signed APK в Android-среду. | Эмуляторный `adb install`/запуск из *того же* подписанного файла, APK signature/zip validation, отчёт и fail-closed до публикации |
| **QA-03 / частично** | Stage 15: владелец подтвердил установку и работу некоторых функций **без API**. Android 11/15 матрица, OEM-ограничения фона, уведомления, разрешения, восстановление ещё не измерены. | Повторяемый PASS/FAIL по сценариям, lifecycle и журналам без публикации частных данных |
| **QA-04 / открыт** | Нет аппаратных измерений целевых **20k синтетических** заметок: время, PSS, заряд, I/O, отмена. 200k — стресс-сценарий сверх продуктовой цели. | Замеры на устройствах, свободная память и ненарушенные исходные хеши, бенчмарки качества поиска/анализа; у владельца нет жёсткого времени первоначального импорта |
| **DATA-05 / частично** | Сейчас есть ограниченный зашифрованный журнал export/restore; полного восстановления всех заметок, настроек, секретов, ZIP-оригиналов и sync нет. | Отдельное восстановление полного переносимого архива на чистом устройстве, без перезаписи неразобранных конфликтов и потери секретов |
| **SEC-06 / частично** | Личные заметки могут утечь через CI, логи, запросы LLM, экспорт и новые cloud/sync-адаптеры. | Локальное шифрование до облачной отправки, раздельные разрешения на облачный backup и текст LLM-запроса, приватные логи и проверка на устройстве |
| **REL-07 / открыт** | Итоговый `main` ещё содержит базовый Markor, а PR #7 — draft; релизные критерии и процедура промоушена не закрыты. | Проверка лицензий, функциональности, восстановления, документации; явное решение о merge, tag, distribution, откате |

## P1 — ядро, достоверность, поиск и данные

| ID / статус | Долг и риск | Условие закрытия |
|---|---|---|
| **CORE-08 / частично** | Кандидата можно одобрить/отклонить; полноценный UX редактирования, пакетного принятия, разделения, объединения, отзыва и пересмотра не доведён. | Все переходы статусов, provenance, применимость правил автопринятия, отзыв и повторяемый replay; тесты циклов и отмены |
| **CORE-09 / частично** | Утверждения и утверждённые решения должны становиться явно `stale` при изменении/исчезновении исходного фрагмента. | Source-hash/revision проверяется при каждом показе/экспорте; старое утверждение не маскируется под подтверждённый свежий источник |
| **INDEX-10 / частично** | При неполном обходе источник не удаляется из индекса намеренно; это оставляет устаревшие кандидаты. Удаления и переименования требуют безопасной сверки. | Только полный доверенный обход может удалить *производную* запись; partial/permission/timeout сохраняют неопределённость; journal/source не затронуты |
| **INDEX-11 / частично** | Ограничения текущего прототипа: 200k файлов, 2 MiB на Markdown и до 128 эмбеддинг-пассажей на файл — часть содержимого может быть непокрытой даже в библиотеке из 20k. | Честный счётчик охвата и пропусков, масштабируемое чтение/постраничность, тесты больших файлов без OOM |
| **INDEX-12 / частично** | SQLite/FTS/векторный индекс имеет диагностику и ручную пересборку, но требуется тестировать повреждения, миграции и прерывания. | Автоматическая диагностика без потерь источников, явное подтверждение rebuild, восстановление после kill/low-storage |
| **SEM-13 / частично** | Формальная грамматика покрывает ограниченный естественный язык; «полный аудит» ограничен представимыми утверждениями. | Метрики parse coverage, false positives/negatives на синтетических контрольных корпусах; неопределённое не принимается за факт |
| **SEM-14 / частично** | Межзаметочная проверка основана на точных предикатах/аргументах: псевдонимы, разные формулировки, отрицания с контекстом и время не решены. | Проверяемый entity-resolution с ручным подтверждением неоднозначных слияний и двусторонним provenance |
| **RET-15 / частично** | LSH по эмбеддингам даёт приближённое совпадение, не гарантирует полноту; лексический/векторный поиск пока не оценён на едином бенчмарке. | Recall/precision и задержка на малых/больших корпусах, гибридный fallback, тесты синонимов и конфликтующих ответов |
| **LLM-16 / частично** | Модель может придумать цитату, проигнорировать `UNKNOWN` или следовать инструкции из заметки; источник текста не доверен. | Проверка номера и точного диапазона цитат, отказ при отсутствии доказательства, prompt-injection регрессии, явный статус AI-ответа |
| **LLM-17 / частично** | OpenAI-compatible сетевые chat/embedding endpoints есть, но **Android-local модель** и её fallback отсутствуют; API-провайдеры, таймауты, квоты и политики хранения различаются. | Контрактные тесты трёх режимов, отказ без модели, лимиты ресурсов/расходов и контекстная авторизация |
| **REVIEW-18 / частично** | Очередь семантических кандидатов нуждается в фильтрах (не просмотрено, ошибочно, повторно, устарело), дедупликации и приоритетах. | Обозримое управление тысячами кандидатов без потери статуса/источника; нет неявного одобрения |
| **SCHED-19 / частично** | WorkManager Stage 14 — периодическая локальная проверка FTS, не полноценный live watcher и не фоновая LLM-обработка; force-stop/OEM режимы не измерены. | Чёткое ожидание UX, адаптивный бюджет батареи, корректные retry, cancellation и count-only notifications на устройствах |
| **UX-20 / частично** | Текущая оболочка Markor — прототип; **утверждён полностью новый интерфейс** с динамическими темами, неблокирующим прогрессом, diff и масштабируемыми списками. | Современная навигация/редактор/аудит/ассистент/backup, доступность, отзывчивость во время 20k-скана, никакой зависимости от CLI |
| **PERF-21 / частично** | Универсальный APK около 75 MB включает Python/ABI runtime; ресурсы большого vault и процесс смерти не профилированы. | Замеры размера, PSS, запуска, батареи; решение об ABI-split/AAB без потери доступного signed APK |
| **BACKUP-22 / частично** | Старый `.dpks` экспорт ограничен 8 MiB и PBKDF2-HMAC-SHA1 (раньше для API 24); новая платформа может выбирать более современный API/KDF, но миграции необходимы. | Версионированное шифрование, перенос 20k заметок и секретов, потоковая проверка/восстановление, отсутствие уничтожения прежнего журнала |
| **STORAGE-23 / частично** | Android SAF/глобальное разрешение хранилища, симлинки, скрытые файлы и изменения файлов внешними программами могут давать частичный обход. | Матрица разрешений Android 11/15, реальные папки и read-only гарантия; любые неполные сканы отмечаются |
| **DOC-24 / частично** | Часть исторических документов CLI может отставать от схемы публичного репозитория и новой Android-архитектуры. Таблица путей в `docs/ARCHITECTURE.md` уже скорректирована, но нужен сквозной doc-review. | Проверить все старые указания путей/экспорта и привести к `SECURITY.md`; различать пользовательское пространство, репозиторий и app-private storage |

## P1 — вновь утверждённые обязательные работы

| ID / статус | Долг и риск | Условие закрытия |
|---|---|---|
| **PORT-33 / открыт** | Android и `ksys` пока связаны встроенным Python/Chaquopy; новая архитектура требует независимого платформенного контракта ядра. | Вынесенный версионированный интерфейс, Android adapter без зависимостей внутри ядра, golden parity tests; новый `minSdk` выбран и протестирован |
| **POLICY-34 / открыт** | Нет механизма пользовательских строгих политик **пакетного/автоматического принятия**. Ошибка может превратить слабую гипотезу в факт. | Scope+schema+source hash+conflicts+provenance, явное включение, dry-run, неизменяемый policy ID в журнале, revoke/replay и тесты ложноположительных решений |
| **ZIP-35 / открыт** | Нет автоматически создаваемого ZIP-снимка **оригинальных** источников внутри приложения и обязательной копии до рискованной правки. | Верифицированный ZIP/manifest с байтовыми SHA-256, нет path traversal, проверка нехватки места, rollback и сохранение последней пригодной копии |
| **EXPORT-36 / открыт** | Нет полного переносимого export/import **всех** пользовательских заметок, настроек, правил, журнала и подключений. | Отдельный формат/миграции, шифрованный полный слепок, dry-run, selective merge, тест на чистом устройстве без потерь |
| **KEY-37 / открыт** | Ключи API сейчас не сохраняются; требуется Android Keystore плюс защищённый парольный экспорт секретных значений (не ключей Keystore). | Device-bound encryption, reauth для экспорта, отдельный ключ архива, импорт в новый Keystore, отсутствие plaintext в ZIP/логах |
| **BACKUP-38 / открыт** | Нет **ежедневного** локального резервирования по умолчанию, настроек периода/retention/места и независимых внешних копий. | Best-effort scheduler, интерфейс успеха/ошибки, учёт места и source SHA; копия переживает удаление приложения, если пользователь настроил внешнее назначение |
| **CLOUD-39 / открыт** | Google Drive пока не подключён как опциональный backup backend; облачные ошибки и права доступа не тестировались. | Пользовательский OAuth/выбор папки, минимальные scope, шифротекст до сети, отзыв доступа, ретраи, независимый статус local/cloud |
| **SYNC-40 / открыт** | Нет собственной синхронизации + безопасного объединения конкурирующих **авторитетных** журналов между устройствами. | Иммутабельные события, причинные ссылки, проверка целостности, конфликт вместо last-write-wins, cross-device replay/merge на синтетике |
| **UI-41 / открыт** | Полный UX redesign вместо оболочки Markor ещё не реализован; крупные списки и фоновая работа не профилированы. | Динамические темы, эффективный рендеринг, процессы, прогресс/отмена, diff, accessibility, навигация без блокировки UI |
| **IMPORT-42 / частично** | Совместимость с Obsidian целевая **только в части импорта/анализа**; полного набора плагинов не требуется. Есть риск потери ссылок/frontmatter/вложений. | Синтетический Obsidian-like корпус, корректный разбор и сохранение оригиналов, явный отчёт неподдерживаемых конструкций |
| **MODEL-43 / открыт** | On-device inference обязателен как **опциональный модуль**, но устройство может не иметь подходящих ресурсов. | Три provider adapter, предварительная оценка RAM, отмена, переключение, отсутствие обязательной загрузки модели/сети |

Подробные контракты: [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md) и
[SYNC_BACKUP_ARCHITECTURE.md](SYNC_BACKUP_ARCHITECTURE.md). Требования не
являются заявлением, что указанные функции присутствуют в текущем APK.

## Дисциплина учёта

Для закрытия пункта нужны: **конкретный PR/commit**, тест или измерение,
запись остаточного риска, обновление этого реестра и, для функциональных
изменений, обновление [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). `CI green`
без проверки пользовательского сценария не равняется `DONE`. Новые проблемы
добавлять с ID, источником, воспроизводимостью, приоритетом и критерием приёмки.
