# DP Knowledge System — реестр технических долгов

**Проверено по состоянию на 2026-11-19.** Это перечень **известных**, а не
гарантированно всех возможных дефектов. Статусы: **открыт** — решение не
проверено/не внедрено; **частично** — есть прототип или ограничения;
**решение** — сначала нужен выбор владельца; **отложен** — не в ближайшем v1.

Источники: исходники и документация `main`,
[интеграционный roadmap](https://github.com/dpsmpx/DP_Knowledge_System/blob/feature/knowledge-android/docs/ANDROID_ROADMAP.md),
[PR #7](https://github.com/dpsmpx/DP_Knowledge_System/pull/7),
[PR #16](https://github.com/dpsmpx/DP_Knowledge_System/pull/16).
Если запись противоречит фактическому тесту, обновить её с доказательством.

## P0 — установка, целостность, безопасность и выпуск

| ID / статус | Долг и риск | Условие закрытия |
|---|---|---|
| **REL-01 / частично** | Пользователь подтвердил установку и запуск APK `com.dpsmpx.dpks` после загрузки через Termux; прежний сбой загрузки обходится. Побайтовая сверка установленного релизного артефакта и причина прежнего различия SHA-256 не задокументированы полностью. | Сравнить SHA-256 скачанного файла с SHA-256 конкретного GitHub Release, проверить установку/обновление того же APK и зафиксировать результат без личных данных |
| **CI-02 / открыт** | CI проверяет сборку, идентификатор пакета и подпись, но не установку итогового signed APK в Android-среду. | Эмуляторный `adb install`/запуск из *того же* подписанного файла, APK signature/zip validation, отчёт и fail-closed до публикации |
| **QA-03 / частично** | Android 15/API 35: автоматические быстрый и нагрузочный прогоны Stage 15 прошли без FAIL. Остаются вручную непроверенными отсутствие сети, отказ/возобновление после kill и reboot, ограничения OEM, реальная доставка WorkManager и уведомлений, смена разрешений и отмена посреди длительного прогона. Поддержка старых Android не является целью проекта. | Чек-лист с результатами повторяемых испытаний на целевом Android, без приватного текста и путей; вынести ручные проверки в отдельный протокол и не объявлять их PASS по синтетике |
| **QA-04 / частично** | На Android 15 успешно проиндексированы **20 000 синтетических Markdown-файлов** за `6218 ms` (отдельный прогон QA — `19919 ms`), FTS/структурные счётчики сошлись. Это не измерение 200k, PSS, энергопотребления или прерывания; размер настоящего vault и его содержимое не опубликованы. | Повторить с замерами памяти, батареи, I/O и отмены; после отдельного решения о масштабе проверить 200k без OOM; сохранить хеши синтетических исходников |
| **QA-33 / открыт** | Проверить реальные сценарии провайдера LLM/эмбеддингов, в том числе локального: отсутствие сети, ошибки авторизации, таймауты, утечку текста, повторное согласие на outbound; синтетический `EMBED-01` проверяет только математику. | На устройстве с выбранной моделью выполнить сценарии согласия/отказа и проверки исходников до/после; зафиксировать только редактированные/синтетические логи |
| **QA-34 / открыт** | Предусмотрена кнопка копирования отчёта QA; фактическое сохранение полного результата в буфере и пригодность его для последующих этапов не подтверждены отдельным тестом. | Проверить запуск одной кнопкой, отмену, копирование полного редактированного отчёта и отсутствие путей/ключей/содержимого заметок во всех стадиях |
| **SQLITE-35 / открыт** | На Android 15 (SQLite 3.44.5) реальный индекс имеет `PRAGMA quick_check=not-ok` при согласованных независимых структурных счётчиках. На отдельной синтетической БД `quick_check` из read-only соединения тоже `not-ok`, а из read/write — `ok`. Причина на платформе не доказана; реальную БД нельзя без согласия менять ради диагностики. | Доказать причину на искусственной БД с FTS4, сравнить версии SQLite и режимы открытия, добавить отдельную корректную диагностику без ошибочного `healthy=true`; реальные проверки не должны выполнять скрытый rebuild |
| **DATA-05 / частично** | Журнал авторитетен, экспорт/восстановление есть в ветке, но реальные ошибки/миграции, нехватка места и большие журналы не пройдены. | Проверить отсутствие перезаписи, целостность цепи, backup/restore на чистом устройстве, ошибочный пароль, обрыв и переход версий |
| **SEC-06 / частично** | Утечка содержимого vault через CI, логи, экспорт, сетевые запросы, промпты или сторонние SDK остаётся главным риском. | Приватность всей цепочки проверена на устройстве и в CI; ни один автоматический запрос не передаёт данные; отдельное согласие на каждый outbound-контекст |
| **REL-07 / открыт** | Итоговый `main` ещё содержит базовый Markor, а PR #7 — draft; релизные критерии и процедура промоушена не закрыты. | Проверка лицензий, функциональности, восстановления, документации; явное решение о merge, tag, distribution, откате |

## P1 — ядро, достоверность, поиск и данные

| ID / статус | Долг и риск | Условие закрытия |
|---|---|---|
| **CORE-08 / частично** | Кандидата можно одобрить/отклонить; полноценный UX редактирования, разделения, объединения, отзыва и пересмотра не доведён. | Все переходы статусов с журналом, правкой доказательств и ревизией затронутых выводов; тесты циклов и отката |
| **CORE-09 / частично** | Утверждения и утверждённые решения должны становиться явно `stale` при изменении/исчезновении исходного фрагмента. | Source-hash/revision проверяется при каждом показе/экспорте; старое утверждение не маскируется под подтверждённый свежий источник |
| **INDEX-10 / частично** | При неполном обходе источник не удаляется из индекса намеренно; до Stage 16 поиск может отображать не встреченные повторно пути как текущие, а производные ссылки могут оставаться устаревшими. | Только полный доверенный обход может удалить *производную* запись; при partial/permission/timeout непроверенные записи видны как неподтверждённые либо исключены из доказательств; отмена атомарна, журнал/Markdown не затронуты; сценарии удаления/переименования проверены на синтетике |
| **INDEX-11 / частично** | Ограничения 200k файлов и 2 MiB на Markdown, до 128 эмбеддинг-пассажей на файл — часть крупной библиотеки остаётся непокрытой. | Честные счётчики охвата и пропусков, масштабируемое чтение/постраничность, тесты больших файлов без OOM |
| **INDEX-12 / частично** | SQLite/FTS/векторный индекс имеет диагностику и ручную пересборку, но требуется тестировать повреждения, миграции и прерывания. | Автоматическая диагностика без потерь источников, явное подтверждение rebuild, восстановление после kill/low-storage |
| **SEM-13 / частично** | Формальная грамматика покрывает ограниченный естественный язык; «полный аудит» ограничен представимыми утверждениями. | Метрики parse coverage, false positives/negatives на синтетических контрольных корпусах; неопределённое не принимается за факт |
| **SEM-14 / частично** | Межзаметочная проверка основана на точных предикатах/аргументах: псевдонимы, разные формулировки, отрицания с контекстом и время не решены. | Проверяемый entity-resolution с ручным подтверждением неоднозначных слияний и двусторонним provenance |
| **RET-15 / частично** | LSH по эмбеддингам даёт приближённое совпадение, не гарантирует полноту; лексический/векторный поиск пока не оценён на едином бенчмарке. | Recall/precision и задержка на малых/больших корпусах, гибридный fallback, тесты синонимов и конфликтующих ответов |
| **LLM-16 / частично** | Модель может придумать цитату, проигнорировать `UNKNOWN` или следовать инструкции из заметки; источник текста не доверен. | Проверка номера и точного диапазона цитат, отказ при отсутствии доказательства, prompt-injection регрессии, явный статус AI-ответа |
| **LLM-17 / частично** | OpenAI-compatible chat/embedding endpoints уже доступны, но реальные провайдеры, сбои API, таймауты, квоты и политики хранения различаются. | Контрактные тесты на локальном/удалённом адаптерах без секретов, обратная совместимость, лимиты расходов и контекстная авторизация |
| **REVIEW-18 / частично** | Очередь семантических кандидатов нуждается в фильтрах (не просмотрено, ошибочно, повторно, устарело), дедупликации и приоритетах. | Обозримое управление тысячами кандидатов без потери статуса/источника; нет неявного одобрения |
| **SCHED-19 / частично** | WorkManager Stage 14 — периодическая локальная проверка FTS, не полноценный live watcher и не фоновая LLM-обработка; force-stop/OEM режимы не измерены. | Чёткое ожидание UX, адаптивный бюджет батареи, корректные retry, cancellation и count-only notifications на устройствах |
| **UX-20 / частично** | Сосуществование Markor-редактора и Knowledge Library требует единой навигации, onboarding, accessibility, пустых/ошибочных состояний. | Новый пользователь выполняет сценарии импорт → поиск → аудит → проверка кандидата → резервная копия без инструкции CLI |
| **PERF-21 / частично** | Универсальный APK около 75 MB включает Python/ABI runtime; ресурсы большого vault и процесс смерти не профилированы. | Замеры размера, PSS, запуска, батареи; решение об ABI-split/AAB без потери доступного signed APK |
| **BACKUP-22 / частично** | `.dpks` экспорт ограничен 8 MiB, версия KDF PBKDF2-HMAC-SHA1 для совместимости с API 24; нет ротации ключа или потокового восстановления. | Версионирование формата, безопасное KDF-обновление/миграция, потоковая проверка, полное тестирование без удаления чужого журнала |
| **STORAGE-23 / частично** | Android SAF/глобальное разрешение хранилища, симлинки, скрытые файлы и изменения файлов внешними программами могут давать частичный обход. | Матрица разрешений Android 11/15, реальные папки и read-only гарантия; любые неполные сканы отмечаются |
| **DOC-24 / открыт** | В части исторических документов CLI есть формулировки из прежней модели приватного репозитория (например, `docs/ARCHITECTURE.md` о журнале/отчётах в Git). | Привести пути и рекомендации к публичной политике `SECURITY.md`; различать рабочую папку пользователя и исходники репозитория |

## Дисциплина учёта

Для закрытия пункта нужны: **конкретный PR/commit**, тест или измерение,
запись остаточного риска, обновление этого реестра и, для функциональных
изменений, обновление [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). `CI green`
без проверки пользовательского сценария не равняется `DONE`. Новые проблемы
добавлять с ID, источником, воспроизводимостью, приоритетом и критерием приёмки.
