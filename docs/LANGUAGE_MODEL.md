# LANGUAGE_MODEL — естественный язык → формальное представление

Код: `ksys/language/` (токенизация, стеммер, лексикон, маркеры, сегментация), `ksys/parser/` (грамматика CNL → LF), `ksys/semantics/` (LF → IR, пересказ, фасад формализации); адаптер импорта — `ksys/importer/language_analyzer.py`.

## 1. Принцип
```
СВОБОДНЫЙ ТЕКСТ ──► [контролируемый язык (CNL) | формальная запись KSF] ──► IR
```
Система **не пытается понять любой русский текст**. Она распознаёт явно определённое подмножество — контролируемый язык в духе Attempto ACE — и формальный синтаксис KSF (`FORMAL_IR.md`).

Всё вне подмножества получает `NO_PARSE` **с причиной**, а не «примерный» разбор. Если подмножество допускает несколько прочтений, возвращаются **все** (`AMBIGUOUS`) и выбирает человек.

Языковой слой отделён от логического ядра: он ничего не пишет в базу, а только предлагает интерпретации.

## 2. Конвейер одного входа (наблюдаемый)
```
SOURCE → TOKENS (language/tokenize) → PARSE: все LF (parser/cnl) → SEMANTIC UNITS: IR (semantics/build)
       → CANONICAL PARAPHRASE (semantics/paraphrase) → статус: FORMALIZED | AMBIGUOUS | UNRESOLVED | NO_PARSE
```
Каждое прочтение имеет `reading_id = RD:<хеш LF>` и метки выбора (`coord=collective`, `sense=owns`, `adj-scope=wide`, `ref=он→V1` …).

## 3. Морфология и нормализация
- Стеммер Snowball для русского (`language/stem.py`), проверен на эталонных выходах snowball. Латиница — нижний регистр без стемминга, `ё → е`, NFC.
- **Ключ понятия** = основы слов через `_`: «языком программирования» и «язык программирования» → `язык_программирован`.
- Тот же нормализатор используется для символов KSF: `is_a(python, интерпретируемый_язык)` и «Python является интерпретируемым языком» дают **один ID** (тест `test_ksf_and_cnl_share_keys`).
- Краткие прилагательные приводятся к полной форме: «вреден» → `вредн` (как «вредный»).
- Ограничение: Snowball может склеить разные слова с общей основой, а для имён даёт неинтуитивные основы («Иван»/«Ивана» → `ива`). Склейку можно разрешить алиасами в журнале.

## 4. Конструкции контролируемого языка
| Конструкция | Пример | IR |
|---|---|---|
| связка | «Python является интерпретируемым языком», «X — Y», «X — это Y» | `is_a(python, интерпретируем_язык)` |
| отрицание | «Алекс не является программистом», «X — не Y», «Кофе не полезен» | `not is_a(…)` |
| прилагательное как класс | «Python — быстрый», «Кофе вреден» | `is_a(python, быстр)` (ADR-008) |
| обладание | «у X есть Y», «X имеет Y», «X имеет свойство Y» | `has`, `has_property` |
| значение | «Возраст Алекса равен 30», «… составляет 30 лет» | `value(алекс, возраст, 30)`, `measure(…, "лет")` |
| глагол из лексикона | «Стресс вызывает бессонницу», «… приводит к бессоннице» | `causes(стресс, бессонниц)` — синонимы сводятся к одному предикату |
| сравнение | «Python лучше Java», «Алекс старше Анны» | `better_than`, `older_than` |
| сочинение | «Алекс использует Python и Git», «… и работает с Git» (общий субъект) | несколько атомов |
| кванторы → правила | «Каждый разработчик использует Git», «Все кошки являются животными», «Ни один кот не является собакой» | `uses(?V1, git) :- is_a(?V1, разработчик)` |
| условие | «Если X является разработчиком и X работает с Python, то X использует Python», «Если кто-то …, то он …» | хорновское правило |
| директива | «Отношение «является частью» транзитивно» | правило транзитивности |
| определение | «Определение: алгоритм — это …», «Под X понимается Y», «X означает Y», неявное «X — это Y, который …» | `Definition` + `is_a(термин, род)`; определяющая часть — текст (PARTIAL) |
| модальность | «Возможно, …» (гипотеза), «Обычно …», «Python обычно выполняет код» | `~possible`, `~usually` |
| заявление | «По словам врача, …», «Согласно X, …», «Иван утверждает, что …» | `claim by врач: …` |
| мнение / наблюдение | «Я думаю, что …», «Я заметил, что …» | `knowledge_type = PERSONAL_OPINION / PERSONAL_OBSERVATION` |
| предпочтение | «Мне нравится кофе», «Я люблю чай» | `likes(me, коф)` — PERSONAL_PREFERENCE |
| контекст | «В контексте работы: …», «В проекте X: …» | `in работ` |
| время | «с D1 по D2», «с D», «до D», «в 2025 году», «в мае 2025», «1 января 2025», `2025-01-01` | интервал `@[…]` |
| решение | «Решение: перейти на Linux, потому что Linux является бесплатным» | `decision "…" because F:…` (основание — ссылка на содержание) |
| вопрос | «Верно ли, что …?», «Является ли X Y?», «Кто использует Python?» | `?- …` |

Лексикон (`language/lexicon.py`) — конечный список глагольных значений (≈45) и сравнительных степеней (16). Его можно расширить файлом `lexicon.json` в рабочем пространстве. Неизвестный глагол даёт `NO_PARSE: no predicate`: предикат никогда не выдумывается из основы слова.

## 5. Неоднозначность (никогда не угадываем)
| Тип | Пример | Прочтения |
|---|---|---|
| собирательное / распределительное | «Алекс и Анна владеют домом» | каждый владеет — или группа владеет (с явными `member_of`) |
| лексическая | «Алекс держит магазин» | `owns` / `holds` |
| область прилагательного | «Старые книги и журналы полезны» | старые только книги — или и журналы |
| область зависимого (справа) | «сбор и организация знаний» | «знаний» относится к обоим — или только ко второму |
| общее главное слово | «комбинация лёгкости, аэродинамики и эргономики» | три отдельных субъекта — или одна ИГ |
| граница атрибута и владельца | «средняя скорость поезда …» без опознавательной заглавной буквы | все разбиения |
| антецедент местоимения в правиле | «Если кто-то знает что-то, то он использует его» | все привязки |

Выбор человека сохраняется в журнале (`resolve`: origin → reading_id) и применяется детерминированно при повторной встрече того же origin.

## 6. Неразрешённые ссылки (UNRESOLVED_REFERENCE)
«Он использует Python», «Мы используем Git», «Ваш мозг любит …», «Температура равна 20» (чья?) → **ни одного IR-узла**. Вместо этого задаётся вопрос («Кто или что обозначено словом «Он»?»).

После ответа (`bind`: origin + слот → сущность) формализация повторяется. Подлежащее «я» однозначно (`me`) и вопроса не требует.

## 7. Что сознательно НЕ поддерживается (NO_PARSE с причиной)
Придаточные (`который`, `чтобы`), дизъюнкция (`или`), обобщённые кванторы (`некоторые`, `многие`, `большинство`), модальные предикативы (`нужно`, `можно`, `должен` — это план или норма, а не факт), предложные группы внутри ИГ (неясно, к чему они присоединяются), пассив и неперечисленные возвратные формы, повелительное наклонение, инфинитивы и личные формы глагола внутри ИГ, начало с союза («А …», «То есть …»), скобки и `;`, английский текст, тире между именами («Паоло Коэльо - Алхимик» — разделитель, а не связка), диапазоны («8–10»), глагол или связка с заглавной буквы в середине строки (заголовки, UI).

Эти классы ошибок проверяются синтетическими примерами; реальные пользовательские заметки не входят в публичный набор тестов.

## 8. Канонический пересказ
Пересказ строится **только из IR**: если смысл потерян при формализации, это видно по расхождению с оригиналом.
```
ORIGINAL:   Стресс приводит к бессоннице.
FORMAL:     causes(стресс, бессонниц).
CANONICAL:  Стресс вызывает «бессоннице».
```
Ярлыки сущностей выбираются так: ярлык из журнала (`label`) → поверхностная форма из предложения → ключ. Пока у понятия нет сохранённого ярлыка, падеж в пересказе может не согласовываться с глаголом — это известное ограничение без морфологического синтеза. Для подлежащего «я» глагол согласуется («Я люблю «кофе»»).

## 9. Ограничения покрытия
Свободный язык неоднозначен: фрагменты вне контролируемой грамматики получают статус `NO_PARSE` или `UNRESOLVED`, не превращаясь автоматически в факты. Доля покрытия зависит от конкретного корпуса. Измерения пользовательских заметок не публикуются.

Все кандидаты из импорта — **заявления источника** (`Claim`), ни один не становится фактом без решения человека.
