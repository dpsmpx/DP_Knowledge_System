# MODEL-M0/M1/M2 — первый Android-срез, не inference

**Ветка:** Stage 18/19 Android integration. **Статус:** реализация файлового
хранилища, SAF-импорта и ручной HTTPS-загрузки; Android/JVM CI и
физический QA должны подтверждаться для каждого PR. [Полный утверждённый план](https://github.com/dpsmpx/DP_Knowledge_System/blob/main/docs/LOCAL_AI_MODELS_PLAN.md)
остаётся источником требований, включая MODEL-M3–M8.

## Реализовано в этом срезе

- Чистая Java-политика четырёх необязательных ролей и четырёх режимов
  провайдера: OFF / Android / собственный ПК / облако. Ни один режим не
  даёт автоматического разрешения отправлять заметки. Без backend
  локальная роль явно помечается `NOT_IMPLEMENTED`, **не** переключается
  на API автоматически. Каталог предлагает по два и более варианта роли.
- Раздел **Управление → Локальные нейросети** с отдельными категориями,
  состоянием «выключено», предложенными вариантами (ссылки на страницы,
  **не** автоматическая загрузка), установленными файлами, отметкой
  предпочтительного файла и подтверждённым удалением.
- Пользователь вручную выбирает через Android SAF `.gguf` или `.onnx`.
  Копирование в app-private `files/dpks-models-v1` происходит только по
  пользовательской команде в отдельном потоке; **DPKS не вызывает AI API**
  и не отправляет содержимое заметок. Однако выбранный SAF-провайдер
  Android (например, облачный диск) сам может использовать сеть для выдачи
  выбранного файла. Используется SHA-256 копируемых байтов, content-addressed blob,
  приватная метазапись на каждую роль, проверка GGUF magic/version,
  атомарное появление метаданных, ограничение свободного места и отмена.
  Размер и SHA показаны пользователю; ONNX помечен как **непроверенный**.
- Хранить несколько вариантов можно без перезаписи; общий blob не
  удаляется, пока на него указывает другая роль. `Off` не вызывает
  сброс Markdown/FTS/журнала, а удаление не касается других файлов.
- Пользователь может явно вставить **прямую публичную HTTPS-ссылку** на
  единичный `.gguf`/`.onnx` (ссылки на каталог/страницу модели сами по
  себе не скачиваются). Отдельное подтверждение показывает домен и имя;
  длина неизвестна до ответа сервера, лимита веса в приложении нет.
  Файл загружается в фоне без AI API, авторизации и доступа к заметкам;
  HTTP/непубличные адреса, credentials, нестандартные порты, web-страницы,
  некорректные redirects и обрывы заявленной длины отвергаются. Поддержаны
  HTTPS-редиректы на CDN. Есть прогресс, отмена и **опциональный** SHA-256
  для проверки ожидаемого дайджеста *до* публикации файла в списке.
  Если SHA не указан, он лишь вычисляется — подлинность источника
  **не подтверждается**. Gated/HF auth-download не предусмотрен.
- `MODEL-M1` каталог прямых артефактов для ручного скачивания:
  **7** конкретных файлов с публичных страниц Hugging Face, с размером
  по источнику (приблизительно), указанной лицензией и *обязательным*
  SHA-256 из страницы каждого файла: 2 варианта E5 Small ONNX, 3 варианта
  Qwen3 GGUF (0.6B Q4/Q8 и 1.7B Q8), 2 варианта Qwen3 Reranker GGUF.
  Нажатие на файл показывает идентификатор, издателя, SHA, приблизительный
  размер, свободное место и предупреждение о совместимости/лицензии;
  скачивание начинается только после подтверждения. Страницы других
  предложенных моделей по-прежнему открываются в браузере; персональный
  классификатор имеет два **плана алгоритма**, но пока не файл весов.
  Источник `resolve/main` может обновиться, но новая последовательность
  байтов будет **отвергнута** прежним ожидаемым SHA, а не молча принята.
  Совпадение SHA установленной модели позволяет показать в подробностях
  известный ID, источник и лицензию. Это **не** проверка tokenizer/backend.
- RU/EN интерфейс явно сообщает, что веса пока **не исполняются**.
  Выбор файла не запускает ИИ; поддержка архитектуры, tokenizer,
  производительность, измерение RAM, автоматическая проверка совместимости
  иных вариантов каталога и четыре synthetic benchmark — **не реализованы**.

## Security/quality gate

- Не импортировать скрипты, `pickle`, архивы, произвольный исполняемый
  код; расширения только `.gguf` и `.onnx`. Заголовок GGUF — *контейнерная*
  проверка, не доказательство работоспособности/подлинности; до запуска
  потребуется валидация adapter/tokenizer и доверенный digest при его
  наличии. Файл пользователя может быть повреждён или вредоносен.
- Имя SAF удаляет разделители пути, управляющие и bidi-format символы;
  приватные URI, пути, исключения и байты не копируются в логи/журнал.
  Метаданные проверяются перед отображением, абсолютный путь к модели
  конструируется только из валидного SHA-256 и поддержанного формата.
- JVM: четыре роли/несколько кандидатов, отсутствие скрытого network
  fallback, сохранность общей модели, удаление, запрет неподдерживаемых
  расширений/неверного GGUF, незавершённый импорт, private name,
  проверка ожидаемого SHA до регистрации, HTTPS URL policy, redirect downgrade,
  ответ HTML, неполный HTTP body и успешная загрузка через CDN.
- В Android CI проверить Java-компиляцию, ресурсы RU/EN, unsigned debug
  APK, Python/regression tests; этот пункт нельзя считать закрытым до CI.
- После подписанного общего prerelease провести реальный QA на **только
  синтетических** данных: SAF file picker, неизвестное имя, 0/много моделей,
  несколько ролей и вариантов, отмена копирования, поворот/фон/kill,
  недостаток диска, удаление общей модели, TalkBack, 200% шрифт,
  подтверждение отсутствия сети и неизменности Markdown/журнала.

## Следующая реализация

1. `MODEL-M1`: дополнить первый SHA-манифест каталогом совместимых
   артефактов со всеми зависимостями/tokenizer, лицензиями/ревизиями,
   паузой/resume и gated HF/license policy;
   полноценная проверка
   импортированных ONNX/GGUF перед использованием.
2. `MODEL-M2`: полноценные экраны со сравнением варианта, расчётным RAM,
   измеренными метриками, статусом загрузки/выгрузки и доступностью.
3. `MODEL-M3`: реальный Android-local embedding backend, tokenizer и
   проверенные совместимые веса; chunker/model-version indexed migration,
   `FTS` fallback и **ручной** синтетический benchmark. Сетевой embedding
   endpoint остаётся отдельным опциональным способом, не скрытой зависимостью.
4. `MODEL-M4–M8`: LLM, реранкер, персонализация, четыре benchmark,
   настоящие device memory/thermal/battery QA согласно основному плану.

**Ни один класс модели пока не выполняет inference в этом срезе; это не
сборка для проверки скорости нейросетей.**
