# DP Knowledge System — проект резервирования и синхронизации

**Статус:** архитектурное предложение, **ещё не реализовано** в таком виде.
Основано на [решениях владельца](OWNER_DECISIONS.md) от 2026-11-18.
Документ фиксирует safety-контракт для последующих PR; криптография,
форматы и API провайдеров проходят отдельный review перед выпуском.

## 1. Три независимых слоя данных

| Слой | Источник истины | Операции |
|---|---|---|
| Markdown и вложения | Оригинальные пользовательские файлы + их версии/хеши | Чтение, явная правка, импорт, ZIP-снимки, файловая синхронизация |
| Решения и политики | Верифицируемые неизменяемые события авторитетного журнала | Добавление событий, проверка цепей, причинное объединение, пересмотр |
| Производные данные | FTS, эмбеддинги, LSH, граф кандидатов, отчёты, кэши | Автоматическая перестройка; отсутствие не считается потерей исходных знаний |

Файловый sync **не является** протоколом объединения авторитетных решений.
Нельзя просто скопировать журнал одного телефона поверх журнала другого.
Внешний Syncthing может передавать оригинальные Markdown-файлы; собственный
адаптер отвечает за журнал и непротиворечивый обмен событиями.

## 2. Исходники в ZIP и ежедневное резервирование

1. При первом присоединении библиотеки предложить создать **снимок
   оригинальных файлов** во внутреннем ZIP-хранилище приложения. До любой
   рискованной массовой операции создавать проверяемый снимок затронутых
   источников **до записи** и не считать действие успешным без его проверки.
2. Каждая запись архива включает исходный относительный путь, байты файла,
   размер, SHA-256, версию источника и безопасную информацию о времени.
   Предотвращать path traversal, симлинки наружу, ZIP bombs и коллизии имён.
3. ZIP — **контейнер содержимого**, не средство шифрования сам по себе.
   Если архив включает личные заметки, долговременная копия шифруется
   **аутентифицированным шифрованием** с версионированным заголовком;
   открытый ZIP не сохраняется в облако или публичные папки по умолчанию.
4. По умолчанию запускать **ежедневное локальное** резервирование, период
   настраиваемый. На Android выполнение фоновой задачи может сдвигаться
   политикой ОС: экран показывает план, фактический срок, последний успех,
   ошибки, объём, запас места и результат проверки архива.
5. Политика хранения настраиваемая. Не удалять последний гарантированно
   восстанавливаемый исходный снимок без явного решения пользователя;
   избегать бесконтрольных полных 20k-файловых копий каждый день,
   использовать версионированные/инкрементальные слепки с проверяемой цепью.
6. **Внутренняя копия недостаточна** при потере/сбросе устройства и
   удалении приложения. Мастер настройки рекомендует независимое внешнее
   место (Android SAF) и поддерживает его выбранную пользователем политику.

## 3. Полный переносимый экспорт / импорт

**Набор данных:** Markdown и вложения, журнал и разрешённые политики,
изменения/ревизии, категории/теги в отдельном слое, настройки, профили
подключений, экспортируемые значения секретов, необходимые конфиги и
манифест версий. Производные индексы можно пересоздать; если они
не включены, это **явно показывается** в отчёте экспорта. Режим полного
слепка может включать и кэши, если формат и объём это допускают.

- Формат: версионированный пакет с манифестом, каталогом ZIP-пейлоадов,
  контрольными суммами, аутентифицированным шифрованием и password-based
  key derivation с явными параметрами. Конкретный KDF/AEAD — предмет
  security review с тестами межверсийной совместимости.
- Локальные секреты защищены **Android Keystore**; ключ Keystore не
  экспортируется. Перед переносом приложения нужно повторное подтверждение
  владельца и пароль архива; **секретные значения** переупаковываются
  в отдельный зашифрованный раздел без раскрытия в файловую систему.
- При восстановлении пароль проверяется до записи; архив проверяется на
  целостность, ссылки, размер, версии и совместимость. Для секретов
  создаётся новый device-local Keystore; неэкспортируемые секреты либо
  вводятся повторно, либо явно отмечаются в отчёте как не перенесённые.
- Импорт — сначала **dry-run**, сравнение имеющихся и входящих данных,
  обнаружение конфликтов, выбор merge/новой библиотеки, а затем атомарное
  применение по отдельным слоям. Не заменять существующие заметки/журнал
  молча; сохранять pre-restore backup и rollback-маркер.
- Проверки: неверный пароль, порча тега, подмена manifest, отсутствие места,
  прерывание процесса/питания, неполная ZIP-структура, разные версии Android,
  версионные миграции, огромная библиотека, повторный импорт, отказ импорта.

## 4. Внешние папки, Google Drive и другие назначения

- **Локальная папка/SAF:** отдельный внешний бэкап по выбору пользователя;
  обновление через временный объект и проверку записанного хеша, когда API
  провайдера это позволяет. Ошибка удалённой записи не объявляется успехом.
- **Syncthing:** совместимость с существующим синком файлов; дубликаты,
  конфликты и временно отсутствующие источники отмечаются, не удаляются
  на основании частичного обхода. Для формальных решений — собственный слой.
- **Google Drive:** пользователь отдельно подключает Google-аккаунт и
  выбирает область доступа/папку. Перед сетевой передачей архив уже
  зашифрован локально; OAuth токены защищены Keystore, минимальные scope
  и возможность отвязать провайдера обязательны. Никаких заметок,
  открытых ключей API или фрагментов в GitHub Actions/логах.
- Настроенный внешний backup может выполняться по ежедневному расписанию,
  **только после явного включения** провайдера. Свежая успешная локальная
  копия и успешная удалённая копия — два разных статуса.

## 5. Авторитетный журнал на нескольких устройствах

Одну глобальную линейную hash-chain нельзя безопасно синхронизировать
обычным `last-write-wins`: два офлайн-устройства могут одновременно
создать разные валидные продолжения одной истории.

**Предлагаемый протокол, подлежащий верификации до внедрения:**

1. Устройство генерирует случайную идентичность участника (не hardware ID).
   Каждый event содержит ID, ссылку на предыдущий локальный event,
   причинные ссылки на известные чужие события, версию источника,
   версию пользовательской политики, актор/основание решения, payload hash.
2. Сначала проверяются цепи, аутентичность партнёра, версия схемы и
   неизменность событий. Синхронизация **добавляет** недостающие валидные
   события, не переписывает чужую историю. Неизвестные версии схемы
   сохраняются как неразобранные и не применяются автоматически.
3. Причинно совместимые события применяются детерминированно. Конкурирующие
   решения об одном знании, удалении или источнике становятся явной
   **веткой конфликта / CONTESTED**, не выбираются по времени телефона.
4. Конфликт показывается пользователю с двумя версиями, provenance,
   diff, возможными последствиями и вариантами нового решения. Результат
   конфликт-резолва — **новое** проверяемое событие, ссылающееся на обе
   ветви, а не редактирование старого журнала.
5. Авторешения по политике синхронизируются вместе с ID и версией этой
   политики. Несовпадение настроек полномочий не даёт чужому устройству
   права расширить локальные полномочия.
6. Миграция текущей единственной цепи выполняется **с проверкой исходной
   истории**, обратимой резервной копией и golden replay-сравнением.
   Кэш и эмбеддинги синхронизировать не обязательно — они пересобираются.

Подтверждение событий и ключей устройств, отзыв устройств, предотвращение
replay/rollback и модель доверия прорабатываются в отдельном ADR. Пункты
выше — **контракт безопасности, не утверждение о готовой реализации**.

## 6. Определение готовности

- 20 000 синтетических заметок: полный первоначальный импорт, повторное
  резервирование, восстановление на чистом Android, совпадение SHA-256;
  никаких скрытых удалений или изменения оригинальных файлов.
- Автоматическое локальное расписание примерно раз в сутки и ручной
  запуск, корректная отмена/повтор при ограничениях батареи и сети.
- Backup/restore secrets с проверкой отказов, пароль не пишется в логи;
  экспорт непереносимых секретов не лжёт об успехе.
- Два офлайн-устройства: независимые решения, доставка вне порядка,
  дубликаты, конфликт, отзыв, новый объединяющий event, потеря сети,
  повторный sync; проверка сохранности всех авторитетных событий.
- Google Drive: opt-in, только шифротекст, успешная повторная загрузка,
  правильный отказ при недоступности, отключение и удаление доступа.
