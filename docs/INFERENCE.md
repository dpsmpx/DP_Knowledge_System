# INFERENCE — логический вывод, TMS, время, SMT

Код: `ksys/inference/engine.py`, `ksys/store/kb.py`, `ksys/temporal/allen.py`, `ksys/query/smt.py`.

## 1. Модель
- **Факты** — ground-утверждения (`Assertion`) с ID `A:h`. Литерал `¬p` — отдельный ключ (сильное отрицание).
- **Правила** — хорновские: `head :- l1, …, ln, сравнения`. В голове может стоять `not p(…)`. Отрицания как неудачи (NAF) нет, поэтому программа монотонна (ADR-005).
- **Исходные и выведенные факты не смешиваются.** У базового элемента (ASSERTED) есть множество источников — записей `F:`/`C:`. Выведенный элемент (DERIVED) существует только при наличии обоснования `DRV:hash(заключение, правило, посылки)`.

## 2. Аннотации при выводе
| Аннотация | Правило комбинирования посылок |
|---|---|
| контекст | встреча: `None` (глобальный) ∧ `c` = `c`; `c1` ≠ `c2` → несовместимо, вывода нет |
| интервал действия | пересечение; пустое → вывода нет |
| модальность | самая слабая (`asserted` > `usually` > `possible`) |
| уверенность | самое слабое звено обоснования, максимум по альтернативным обоснованиям (`provenance/proof.confidence_map`) |

## 3. Вычисление
- Полунаивная неподвижная точка: на каждом раунде правило срабатывает только если хотя бы одна посылка новая (`delta`). Соединения идут по индексам `(предикат, полярность)` и `(предикат, полярность, первый аргумент)`.
- Рекурсия и транзитивность — обычные правила (`#transitive p.` разворачивается в `p(X,Z) :- p(X,Y), p(Y,Z)`).
- **Каждое** срабатывание записывается как обоснование, даже если заключение уже известно. Поэтому множество обоснований полно, и TMS корректен.
- Порядок обхода детерминирован (сортировки по ID), предохранитель — `max_items`.

## 4. Слои
- `auth` — только авторитетное знание (принятые человеком факты и правила).
- `full` — `auth` плюс заявления (`CLAIMED`), записанные человеком. Используется только для статусов SUPPORTED/CONTESTED гипотез и для анализа. Из `full` ничего не попадает в знание без решения человека.

## 5. Truth maintenance (DRed)
```
F1 ─R1→ F2 ─R2→ F3          retract(F1):
                             1) переудаление: всё, что транзитивно зависит от F1 (кроме базовых)
                             2) повторный вывод: элемент восстанавливается, если у него есть
                                обоснование с живыми посылками (итерация до неподвижной точки)
                             3) окончательное удаление элементов и их обоснований
```
- Пересчитывается только затронутая область. Каждая операция возвращает `Delta(added, removed, rederived)`, поэтому при отзыве и пересмотре система называет затронутые выводы.
- Циклическая самоподдержка (`p ← q ← p`) не переживает отзыв опоры (тест `test_cycle_does_not_self_support`).
- **Инвариант** (property-тест на 750 случайных шагах): состояние после любой последовательности добавлений и удалений совпадает с полным пересчётом от оставшихся фактов и правил.
- Пересмотр (`revise`): старая запись → OBSOLETE с `superseded_by`, новая → HUMAN_ACCEPTED с `supersedes`. История сохраняется в журнале.
- Решения (`Decision`) помнят основания. При отзыве факта-основания система сообщает, какие решения потеряли опору.
- «Что будет, если удалить X» (`what_if_retract`) — DRed на копии движка, журнал не меняется.

## 6. Время
- Интервал действия `[start, end]` (дни, открытые концы = ±∞). Факт **не считается истинным вне интервала**: запрос «на дату» учитывает только факты, чей интервал содержит дату (тест `test_temporal_validity`).
- Отношения Аллена между интервалами (`before`, `meets`, `overlaps`, `during`, `starts`, `finishes`, `equals` и обратные) — `temporal.relation`. Исторический срез на дату — `temporal.state_at`.
- Время знания (когда факт истинен) и время решения (когда человек его принял, `ts` в журнале) — разные оси. Второе используется для версий (`--at J:…`).

## 7. Версии знания
Журнал — цепочка knowledge commits. `KnowledgeBase(ws, clock, at="J:…")` воспроизводит префикс журнала и отвечает на вопрос «что система знала раньше». Такой снимок только для чтения. Replay детерминирован: повторное открытие даёт байт-в-байт то же состояние (тест `test_replay_is_deterministic_and_incremental_equals_full`).

## 8. SMT (необязательный бэкенд)
Числовое знание: `value(s, a, N)`, `bound(s, a, "op", N)` (CNL: «Возраст Алекса больше 40»), `attr_cmp(s1, a1, "op", s2, a2)`.
- `smt.consistency(engine)` — выполнимость. При невыполнимости — unsat core из записей (их provenance показывается).
- `smt.entails(engine, s, a, op, n)` — PROVEN / DISPROVEN / UNKNOWN через проверку выполнимости отрицания.
- Без `z3-solver`: детерминированная интервальная проверка для одной переменной. Для `attr_cmp` — `UNKNOWN` с `SMT_UNAVAILABLE`, без догадок.

## 9. Ограничения
- Нет NAF и агрегатов (count/sum): закрытый мир нужно объявлять явно, это roadmap.
- Нет функциональных символов (конечность Datalog гарантирована).
- Равенство сущностей (`same_as`) не выводится. Склейка ключей — только через алиасы при формализации.
