# MODEL-M1 — ручное возобновление загрузки весов

**Статус: реализован механизм для одного файла с заранее известным
SHA-256; M1 целиком не завершён.** Встроенного Android inference нет.

## Контракт

1. Действие начинается только по команде пользователя. Загрузка веса из
   каталога имеет опубликованный SHA-256; при вставке чужой прямой ссылки
   пользователь может вручную ввести ожидаемый SHA-256. **Без него**
   прежний безопасный режим остаётся одноразовым, без сохраняемой части.
2. При обрыве/отмене загрузки с эталонным SHA байты хранятся **только
   в приватной папке приложения** под техническим именем, производным от
   контрольной суммы и формата. URL, токены, текст заметок и имена vault
   там не сохраняются; частичный файл **не зарегистрирован как модель**.
3. При повторном ручном запуске экран показывает размер сохранённой части
   и позволяет явно **«Продолжить»**, **«С нуля»** или отменить операцию.
   Перезапуск удаляет сохранённую часть до получения новых байтов.
4. HTTP-клиент ставит `Range: bytes=<offset>-` только при найденной
   сохранённой части. Ответ `206` принимается только при точном
   `Content-Range: bytes <offset>-<last>/<total>`, где `last=total−1`,
   а тело совпадает по `Content-Length`. Неполный/чужой диапазон не
   добавляется к файлу. Ответ `200`, игнорирующий `Range`, означает
   полный перезапуск с нулевого байта; неожиданный `206` без запроса
   отклоняется. Редиректы остаются только публичными HTTPS.
5. При возобновлении SHA-256 вычисляется **заново по всем сохранённым
   и новым байтам**; дополнительно проверяется GGUF-заголовок. Только
   полное совпадение хеша позволяет атомарно зарегистрировать модель.
   Неверный хеш/контейнер удаляет накопленную часть; сетевой обрыв
   сохраняет её для следующего явного действия.

## Проверки и ограничения

- JVM/синтетика: усечённый `200` → точный `206` → установка; ошибочная
  начальная позиция/конечная позиция/полный размер; неожиданный `206`;
  сервер, игнорирующий `Range`; неверный SHA с удалением части.
- Не утверждается поддержка gate/restricted HF лицензий или авторизации,
  целых каталогов с tokenizer/config, автоматической совместимости
  модели и её исполнения. Эти части остаются в `MODEL-M1/M3`.
- Нужна физическая Android-проверка при потере сети, нехватке места,
  убийстве процесса, SAF и на больших весах. Ни пользовательский vault,
  ни журнал для проверки не нужны.
