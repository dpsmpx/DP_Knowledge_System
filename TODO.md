# DP Knowledge System — вопросы и внешняя приёмка Stage 21

Состояние: 20.11.2026. Это перечень вопросов, требующих решения владельца,
и проверок, которые нельзя честно выполнить без его Android-устройства.
Не содержит личных заметок, имён устройств, паролей и учётных данных.

## Решения, уже принятые (не переспрашивать)

- Сначала SAF/Syncthing/Google Drive через стандартную папку Android;
  собственная автоматическая передача — после безопасного протокола.
- Для сопряжения — QR либо одноразовый проверочный код, доверие отзывается.
- Конфликты остаются отдельными ветвями до ручного подтверждения; ничего
  не объединяется по дате, источники Markdown никогда не перезаписываются.
- Локальный ежедневный зашифрованный backup — только после явного включения;
  никаких автоматических скачиваний моделей эмбеддингов.
- APK не создавать до отдельного распоряжения владельца.
- Все ответы на открытые вопросы Stage 21 получены через опрос 20.11.2026;
  дальнейшие работы ведутся по зафиксированным решениям ниже.

## Инженерная передача

- [x] **DEV-21-22 — перенос доступных секретов (исходники и тесты).**
  Добавлена схема настроек v3 с отдельно сверяемым через manifest файлом
  `meta/secrets.json` и строгим списком `knowledge_embedding_endpoint`,
  `knowledge_llm_endpoint`. Каждый ручной экспорт требует отдельной
  включаемой галочки и повторного подтверждения с перечнем полей; импорт
  секретов отдельно отключён по умолчанию. Ежедневные копии по-прежнему
  используют v2 без секретов. Сеансовый ключ LLM не хранится, приватные
  ключи Keystore неэкспортируемые. **Не закрывает аппаратную проверку**.
- [x] **DEV-21-23 — ручной обмен оригиналами из зашифрованного архива.**
  Добавлен отдельный SAF-выбор DPKSB, постраничный просмотр оригиналов
  Markdown, сравнение SHA и фрагментов обоих текстов, отдельное подтверждение
  копирования и создание нового файла с `peer-<sha>` вместо перезаписи.
  Защита от обхода путей, атомарное создание, контроль свежести исходников
  и SHA после копирования. Для полного просмотра больших Markdown остаётся
  открыть оригиналы вне ограниченного экранного превью. **Отдельный импорт
  обычного `.md` через SAF и аппаратная QA ещё впереди**.
- [x] **DEV-21-24 — прямой ручной импорт `.md` через SAF.**
  Добавлена отдельная кнопка Android/SAF/Syncthing для одного незашифрованного
  Markdown. Перед копированием — сравнительный просмотр, хеши, размер,
  повторное согласие; исходный файл не заменяется, имя проверяется, новая
  копия создаётся атомарно. Временный plaintext удаляется при закрытии
  диалога/Activity и при следующем запуске после аварии. Нужно испытать
  реальный SAF-провайдер, память, права и Unicode-имена на устройстве.
- [x] **DEV-21-25 — Android unit-регрессия Markdown, исправление внесено.** Прогон #200
  (commit `5e17e94`) завершился ошибкой JUnit после успешной Java-компиляции;
  имя кейса не попадало в краткий лог CI. В прогоне #201 новый вывод
  XML обнаружил две одинаковые ошибки `Destination folder escaped selected
  library`: проверка ложно отвергала сохранение прямо в корне библиотеки.
  Исправлено с сохранением строгой защиты вложенных путей. Android CI #202
  (run 44713363668) прошёл на обеих конфигурациях; APK не собирался.
- [x] **DEV-21-26 — долговременный high-water учёт локальных входящих ветвей.**
  Для каждого проверенного подписанного префикса хранится отдельный
  монотонный набор SHA-256 отметок в `noBackupFilesDir`, зашифрованный
  самостоятельным AES-ключом Android Keystore. Удаление записи encrypted
  inbox его не очищает; если файл учёта исчез, но ключ остался, система
  блокирует принятие до явного восстановления. При обновлении старые
  записи inbox дают первичную отметку. Точный откат отклоняется, другие
  подписанные fork остаются доступными. Требуется проверка устройства;
  **экспорт/импорт журнала high-water при переезде — следующий этап**.
- [x] **DEV-21-27 — ручной перенос high-water.** Шифрованный ручной DPKSB
  содержит `meta/highwater.bin` с SHA-отметками без закрытого Keystore-ключа;
  перенос в новую библиотеку требует отдельной выключенной по умолчанию
  галочки. Уже существующие отметки объединяются, а не заменяются.
  Инструкция для проверки на двух устройствах —
  `docs/STAGE21_HIGHWATER_RECOVERY.md`. Аппаратная QA не выполнена.
- [x] **DEV-21-28 — ручные иностранные `alias`, `label`, `schema`.**
  У каждого события — собственный предпросмотр полного ограниченного payload,
  проверка обеих хеш-цепочек, подписанного paired inbox на Android,
  повторная проверка локальной вершины и исходного SHA, второе отдельное
  подтверждение. Вместо чужой строки записывается *новое локальное*
  событие с явными causal-ссылками. Перезапись локальных alias/label,
  неоднозначные символы и неподдерживаемые schema-поля запрещены.
  Без автоматического replay; аппаратная QA ещё не выполнена.
- [x] **DEV-21-29 — ручные `bind` и `resolve`.** По точному `origin` ищется
  *локальная* индексированная заметка, она заново читается, фрагмент и
  прочтение/нерешённый слот проверяются по локальной грамматике. Две явные
  операции UI, повторная проверка подписанного inbox, SHA исходного текста,
  локальной/удалённой вершины; только новое причинное локальное событие.
  Изменённая заметка, неизвестное прочтение, локальный выбор или занятая
  привязка отклоняются. Если локальная библиотека ещё не индексирована,
  пользователь должен запустить существующую индексацию вручную. Аппаратная
  QA не выполнена.
- [x] **DEV-21-30 — ручные `revise`, `split`, `merge`.** Каждое подписанное
  предложение отдельно сверяет все затронутые *активные локальные* записи,
  роли, уникальность и каноничность новых узлов, типы и структурные ошибки.
  UI показывает прежние записи и полное предлагаемое содержание, затем
  просит отдельное повторное согласие. Запись — новое локальное событие с
  causal-ссылками; чужое утверждение о provenance **не** принимается за
  локальное доказательство. Непроверенные / конфликтующие / слишком большие
  изменения блокируются. Аппаратная QA не выполнена.
- [x] **DEV-21-31 — проверка Stage 21 существующими кнопками QA.**
  В существующие быстрый и стрессовый сценарии добавлены синтетические
