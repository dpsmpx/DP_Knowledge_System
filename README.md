# DP Knowledge System

Локальное, детерминированное ядро персональной базы знаний на Markdown. Это **исследовательская основа будущего Android-приложения**, а не готовая замена Obsidian.

Система импортирует Markdown как источник утверждений, формализует поддерживаемые конструкции, различает факт / заявление / гипотезу, предлагает пользователю подтвердить интерпретацию, хранит журнал решений, выполняет объяснимый логический вывод и показывает происхождение ответа. Неподтверждённые утверждения не становятся фактами автоматически; отсутствие доказательства не трактуется как ложь.

## Содержимое

- `ksys/` — Python-ядро: Markdown, контролируемый язык, IR, валидация, импортер, журнал, вывод, диалог и запросы.
- `bin/knowledge` — CLI текущего прототипа.
- `docs/` — архитектура, модели данных, логика и ограничения.
- `tests/` — автоматические тесты на синтетических данных.
- `demo/vault/` — **искусственно составленные примеры**, не настоящие пользовательские заметки.
- `rules/`, `schemas/` — формальные правила и JSON Schema.

## Быстрый запуск

Требуется Python 3.11+; стандартной библиотеки достаточно, `z3-solver` — необязательное дополнение.

```bash
python3 -m unittest discover -s tests -t .
./bin/knowledge demo
cp ks.example.json ks.json
./bin/knowledge import --vault demo/vault
```

Запуск с настоящими заметками допускается **только локально**: поместите vault за пределами репозитория и передавайте путь через `--vault`. Конфигурация `ks.json`, журналы, отчёты, базы данных и кэши игнорируются Git. Не добавляйте личные заметки или результаты импорта в коммиты, issues и PR.

## Архитектурная цель

Android-приложение с управлением крупной Markdown-библиотекой, удобным редактором, поиском, связями, проверяемыми рекомендациями и контролируемой интеграцией LLM. В интеграционной ветке развивается Android-форк Markor в `third_party/markor/`: нативная библиотека заметок, локальный производный полнотекстовый индекс, офлайн-мост к **оригинальному Python-ядру** `ksys`, управляемые решения пользователя с отдельным журналом, вопросы и доказательства через детерминированный движок, а также ручной зашифрованный экспорт и восстановление журнала. Реализован локальный **пакетный смысловой анализ выбранной Markdown-библиотеки**: разбор заметок, классификация, формализация, кандидаты для ручной проверки, инкрементальное обновление и отмена. **Сопоставление утверждений между заметками** выявляет возможные согласия и конфликты по совпадающим формальным предикатам с указанием обоих источников. Автоматический повторный анализ включается пользователем отдельно и запускается при обновлении экрана библиотеки; это ещё не фоновая системная служба. **Факты без подтверждения не принимаются**. Свободный LLM-ассистент теперь доступен как **отдельное действие с подтверждением каждого сетевого запроса**: локальный поиск выбирает до шести выдержек, пользователь видит весь отправляемый текст, а ответ модели помечается непроверенным. Автономного выполнения действий моделью нет. Автоматических резервных копий нет, поэтому перед удалением приложения необходимо сохранить архив журнала и пароль. [Этапы и инварианты](docs/ANDROID_ROADMAP.md).

### Аудит противоречий и неясностей

В Android-ветке доступен **полный аудит локального индекса библиотеки**: приложение заново читает выбранные Markdown-заметки, проверяет потенциальные конфликты между заявлениями источников, противоречия **подтверждённых** знаний, неоднозначные и неразрешённые фрагменты, пропуски грамматики, проблемы импорта, пробелы и целостность журнала. Результаты разбиты на семь категорий с переходом к источникам. Отсутствие найденных противоречий **не является доказательством** непротиворечивости всего естественного языка. Код не исправляет заметки автоматически и не отправляет личные данные в сеть. Подробные ограничения — в [плане Android-интеграции](docs/ANDROID_ROADMAP.md).

### Семантический поиск по эмбеддингам

Добавлен **ручной инкрементальный векторный индекс** с OpenAI-совместимым API `/v1/embeddings`: до 128 ограниченных по длине фрагментов на заметку, нормализованные float32-векторы в приватной базе приложения и точная косинусная оценка выбранных кандидатов. Для индексации пользователь отдельно подтверждает передачу фрагментов выбранному серверу — автоматической отправки нет. Вопрос для смыслового поиска также требует отдельного разрешения; сами заметки во время запроса поиска не передаются. При обращении к LLM можно выбрать смысловой подбор источников и затем проверить точный текст отправляемых выдержек. Для модели эмбеддингов необходим отдельный совместимый сервер, например LM Studio на ПК; приложение не содержит весов модели. Сходство векторов **не означает истинности** текста. Ограничения охвата — в [плане Android-интеграции](docs/ANDROID_ROADMAP.md).

**Обновление этапа 12:** вместо прежней выборки из трёх разрозненных фрагментов индексатор последовательно выделяет перекрывающиеся блоки Markdown с учётом заголовков и абзацев, до **128 фрагментов на заметку**. Долгую обработку можно прервать и затем продолжить с последнего сохранённого блока. Старые векторы при обновлении схемы сохраняются; их замена происходит только после нового разрешения. Поиск использует локальные индексируемые LSH-корзины для предварительного отбора и точно вычисляет косинусную близость кандидатов. **Это приближённый поиск:** некоторые близкие фрагменты могут не попасть в выдачу. Особенно длинные документы, превысившие лимит фрагментов, отмечаются как охваченные не полностью. Подробности: [этап 12](docs/ANDROID_ROADMAP.md).

### Надёжность больших библиотек — этап 13

Сканирование и обновление локального поискового индекса теперь показывают **прогресс по количеству заметок**, не раскрывая содержимое и имена файлов. Отдельный экран диагностики проверяет целостность SQLite, согласованность полнотекстовых записей и связанных векторов, а также показывает результат последнего успешно завершённого сканирования. Данные о завершении фиксируются одной транзакцией с индексом: прерванный проход не считается успешным.

Если производный индекс повреждён или требует восстановления, пользователь может **отдельно подтвердить его пересоздание** с офлайн-сканированием. При этом не меняются Markdown-заметки и журнал подтверждённых знаний; ранее сохранённые эмбеддинги удаляются и при необходимости создаются снова **только с новым явным разрешением**. Добавлены синтетические нагрузочные тесты обхода и отмены, но постоянные фоновые задания и испытания на реальном устройстве — задачи следующего этапа. Подробнее: [этап 13](docs/ANDROID_ROADMAP.md).

## Безопасность и происхождение

Этот репозиторий создан **с новой историей**: из закрытого хранилища перенесены только выборочно проверенные, очищенные исходники и искусственные примеры; отдельно добавлен общедоступный исходный код Markor. Исходное персональное хранилище, приватные ветки и история коммитов не импортированы. Синтетические примеры не описывают владельца проекта. Подробности: [SECURITY.md](SECURITY.md).
