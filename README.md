# DP Knowledge System

Локальное, детерминированное ядро персональной базы знаний на Markdown. Это **исследовательская основа будущего Android-приложения**, а не готовая замена Obsidian.

## Состояние разработки и дальнейшие планы (18.11.2026)

`main` содержит Python-ядро и базовый исходный снимок Markor. **Android-интеграция этапов 01–14 существует отдельно** в [`feature/knowledge-android`](https://github.com/dpsmpx/DP_Knowledge_System/tree/feature/knowledge-android) и собрана в [черновом PR #7](https://github.com/dpsmpx/DP_Knowledge_System/pull/7), который пока не следует сливать в `main` без проверки на устройствах. Подписанный тестовый APK публиковался в Releases, но успешная установка и аппаратное принятие **не подтверждены**; замечено различие контрольных сумм скачанного на телефон и опубликованного файлов.

- [**План дальнейшей разработки**](docs/DEVELOPMENT_PLAN.md) — статус, Stage 15+, критерии приёмки, последовательность PR, идеи после v1.
- [**Реестр технических долгов**](docs/TECHNICAL_DEBT.md) — приоритеты, риски, проверяемые условия закрытия.
- [**Вопросы к владельцу проекта**](docs/OWNER_DECISIONS.md) — архитектурные и продуктовые решения, которые нельзя принимать без ответа.
- [Отложенные задачи](docs/BACKLOG.md) — включая отдельную систему повествований B-001.

Документы намеренно различают **«реализовано в интеграционной ветке»**, **«проверено в CI»** и **«принято на реальном Android»**. Наличие APK в релизе не доказывает его пригодность к установке.

Система импортирует Markdown как источник утверждений, формализует поддерживаемые конструкции, различает факт / заявление / гипотезу, предлагает пользователю подтвердить интерпретацию, хранит журнал решений, выполняет объяснимый логический вывод и показывает происхождение ответа. Неподтверждённые утверждения не становятся фактами автоматически; отсутствие доказательства не трактуется как ложь.

## Содержимое

- `ksys/` — Python-ядро: Markdown, контролируемый язык, IR, валидация, импортер, журнал, вывод, диалог и запросы.
- `bin/knowledge` — CLI текущего прототипа.
- `docs/` — архитектура, модели данных, логика и ограничения.
- `tests/` — автоматические тесты на синтетических данных.
- `demo/vault/` — **искусственно составленные примеры**, не настоящие пользовательские заметки.
- `rules/`, `schemas/` — формальные правила и JSON Schema.

## Быстрый запуск

Требуется Python 3.11+; стандартной библиотеки достаточно, `z3-solver` — необязательное дополнение.

```bash
python3 -m unittest discover -s tests -t .
./bin/knowledge demo
cp ks.example.json ks.json
./bin/knowledge import --vault demo/vault
```

Запуск с настоящими заметками допускается **только локально**: поместите vault за пределами репозитория и передавайте путь через `--vault`. Конфигурация `ks.json`, журналы, отчёты, базы данных и кэши игнорируются Git. Не добавляйте личные заметки или результаты импорта в коммиты, issues и PR.

## Архитектурная цель

Android-приложение с управлением крупной Markdown-библиотекой, удобным редактором, поиском, связями, проверяемыми рекомендациями и контролируемой интеграцией LLM. **В `main`** Python-ядро и Markor пока остаются отдельными компонентами. **В интеграционной ветке** уже выполнен значительный объём Android-кода, однако он ещё не принят для финальной версии и не перенесён в `main`.

## Безопасность и происхождение

Этот репозиторий создан **с новой историей**: из закрытого хранилища перенесены только выборочно проверенные, очищенные исходники и искусственные примеры; отдельно добавлен общедоступный исходный код Markor. Исходное персональное хранилище, приватные ветки и история коммитов не импортированы. Синтетические примеры не описывают владельца проекта. Подробности: [SECURITY.md](SECURITY.md).
